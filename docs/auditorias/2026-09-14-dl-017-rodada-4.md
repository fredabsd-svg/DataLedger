### 1. "Fechamos a classe ou de novo só o caso?" — **de novo só o caso, nos três**

**BL-115 — "nenhum número do cliente dimensiona laço".** Fechada para laço: varri todo `range()` de produção, só existem os dois desta view, os dois capados. **Mas a classe irmã ficou aberta.** Varri todo `int()` de entrada de cliente e achei **dois** sem proteção:

| `apps/tenancy/views.py:113` | `escritorio_id` com 6000 dígitos | **HTTP 500** |

Os dois são `isdigit()` + `int()` sem `try`. **A lição já está escrita, no mesmo arquivo:** `views_web.py:283-292` explica que `isdigit()` aceita dígito Unicode e que `int("9"*5000)` é um 500, e diz "a API já tinha as duas lições aplicadas… reaproveitado aqui, não duplicado". Aplicado ao campo que o relatório nomeou, e a nenhum outro.

`request.FILES` é uma entrada estruturada que esta view **nunca olha**, e `_indices_de_linha_do_post(request.POST)` não pode recusar o que não vê — a **mesma causa raiz** que a própria BL-116 nomeia ("para poder RECUSAR uma chave malformada, a busca precisa primeiro ENCONTRÁ-LA"), num dicionário diferente.

Na mesma dimensão, e menores: `CONTA_3`/`Conta_3` (prefixo em caixa diferente) → **302, ignorados em silêncio**; `conta_1` em dígito *fullwidth* `７` → **302, reinterpretado como a conta 7**.

### 2. "DE-030 e DE-031 se sustentam?" — **a DE-030 se sustenta para o que ela nomeia; o caso que ela não cobre é a data**

A DE-030 legisla sobre **valor monetário**. O sistema tem outro campo com exatamente os mesmos dois defeitos que o R3-3 apontou, e ela não o alcança. Medido, pela API real:

### 3. "Procure um quarto teste que não consiga falhar" — **encontrei, e é o que mede a própria BL-119**

`apps/contabilidade/tests/test_dl017_rodada2_frontend.py:901`, `test_indentacao_por_efeito_pula_com_motivo_quando_nao_ha_navegador`. O corpo é:

`_chromium_funciona` devolve `False` ou o resultado de uma comparação — **sempre um `bool`**. A primeira asserção é uma tautologia. E o comentário do módulo (linha 593) cita este teste nominalmente como prova de que os testes de efeito ficam "honestamente pulados" na CI.

**Um bônus da mesma família, em sentido inverso (A6):** `test_linhas_lancamento_do_post_capa_num_linhas_mesmo_em_chamada_direta` chama a função com `10**12` e afirma `duracao < 1`. Um teste cujo modo de falha é pendurar não reprova um build: ele estoura o `timeout-minutes: 10` do workflow com uma causa que não se parece com a causa. E o defeito que ele defende é, literalmente, "a requisição não volta".

### A1 — MÉDIA · `conta_id` com mais de 4300 dígitos derruba a gravação com HTTP 500

**Requisito:** critério 13; R2-2 (a mesma classe, já fechada para `nivel`); AGENTS.md §1 (validação no servidor).
**Local:** `/home/user/DataLedger/apps/contabilidade/views_web.py:749` —
```python
conta = contas_por_id.get(int(linha["conta_id"])) if linha["conta_id"].isdigit() else None
```
**Reprodução.** POST autenticado na tela de lançamento, duas partidas válidas, com `conta_1 = "9" * 4301`:

| `conta_1` | HTTP |
|---|---|
| `"9"*4299` | 400 (correto) |
| **`"9"*4301`** | **500** — `ValueError: Exceeds the limit (4300 digits) for integer string conversion` |
| `"9"*6000` | **500** |
| `"７"` (fullwidth, id 7) | **302 gravado, reinterpretado como a conta 7** |

**Impacto.** 500 cru alcançável por qualquer usuário autenticado com um POST construído à mão (o campo é um `<select>`; alterar o valor é um clique no inspetor). Não corrompe dado. O caso *fullwidth* é reinterpretação silenciosa de entrada — a política que a DE-029 proíbe —, sem vazamento entre empresas porque `contas_por_id` já está escopado.

E **varrer todo `int()`/`isdigit()` sobre entrada de cliente do repositório**, não só este.
**Como verificar:** `"9"*4301`, `"9"*6000`, `"７"`, `"٢"` em `conta_N` devolvem **400**, nunca 500 e nunca 302 com outra conta.
**Responsável:** `especialista-frontend`.

### A2 — MÉDIA · `escritorio_id` com mais de 4300 dígitos derruba a troca de escritório com HTTP 500

**Requisito:** critério 13; R2-2; a mesma classe do A1, em outro app.
**Local:** `/home/user/DataLedger/apps/tenancy/views.py:113-115` — `if not escritorio_id or not str(escritorio_id).isdigit(): … escritorio_id_valido = int(escritorio_id)`.

**Agravante de método:** o comentário imediatamente acima justifica a escolha — *"Validação por string (em vez de try/except sobre int()) evita depender de exceção para um caso de entrada tão comum"*. **Impacto.** 500 numa rota que todo usuário autenticado alcança pelo painel.
**Correção recomendada:** `re.fullmatch(r"[0-9]{1,9}", …)` ou `try/except ValueError`; e, junto com A1, a varredura da classe.
**Como verificar:** `"9"*6000`, `"９"` → mensagem de erro e redirecionamento, nunca 500, nunca aceitação.
**Responsável:** `desenvolvedor-pleno`.
