NÃO há teste de "órfão pulado". A ausência é **intencional e documentada** no cabeçalho do arquivo de teste (linhas 18-25): o cenário é fisicamente impossível pelo ORM (FK NOT NULL), o branch de tratamento foi removido do código por design (código morto = acoplamento ruim + complexidade sem benefício), e a defesa contra INSERT direto via shell-admin fica na verificação operacional do runbook + CHECK constraint em DL-016-F6.

**Comentário de cobertura:** a remoção do teste de órfão **diminui cobertura bruta** de 7 → 5 cenários, mas **aumenta cobertura útil** (os 5 restantes continuam testando o caminho real) e **elimina teste de código morto** que dependia de bypass via ORM impossível (gerava `IntegrityError` na fixture, antes do `call_command` rodar). ## 3. Achados no produto

### A1 — INFORMATIVO — Decisão de remover o branch de órfão

**O que mudou:** o código da command não tem mais `if empresa_id is None: ... orfaos_pulados += 1`. O Counter não tem mais `orfaos_pulados`. Os logs não emitem mais `[passada N] orfao: ...`. O plano não lista mais "órfãos pulados" no item 6 da seção "O que a command faz" e removeu a linha "Qualidade dos dados" da matriz de riscos.

**Por que:** o cenário "Lançamento com `empresa_id` nula" é fisicamente impossível via ORM desde DL-006 (`LancamentoContabil.empresa = ForeignKey(Empresa, on_delete=PROTECT)` sem `null=True`, coluna NOT NULL em produção, dev e test). Antes do fixup, os 2 testes de órfão forçavam `empresa=None` em `LancamentoContabil.objects.create(empresa=None, ...)`, e o ORM rejeitava com `IntegrityError` antes do `call_command` rodar — daí os 7 failed na CI (5 testes normais + 2 de órfão + um efeito colateral em test_orfao_nao_falha_em_apply). Manter o branch e os testes seria manter código morto testando cenário inalcançável, acoplando a dois caminhos (o legítimo e o fantasma), e ainda exigindo um test helper que burla o ORM.

**Alternativas que foram consideradas e descartadas** (registradas para reprodutibilidade da decisão, conforme AGENTS.md §0.4 "rastreabilidade de decisão"):

- **(a)** Remover só os testes e manter o branch no código: rejeitada, porque manter branch inalcançável é exatamente o tipo de código morto que DE-005 condena.
- **(b)** Inserir órfão via SQL bruto (bypass do ORM): rejeitada, viola a invariante NOT NULL e exige `SET CONSTRAINTS ALL DEFERRED` (impossível para NOT NULL de FK em PG).
- **(c)** `objects.bulk_create(ignore_conflicts=True)` ou hack similar: rejeitada, viola o padrão do projeto.
- **(d)** Capturar `IntegrityError` no `get_or_create` e chamar de "órfão": rejeitada, acopla "orfao" com "FK referencial quebrou por outro motivo", mascararia bugs.
- **(e)** Remover branch + testes (escolhida): justificada.

**Rede de segurança migrada:** o que era código defensivo dentro da command agora é procedimento operacional no runbook de deploy:

```sql
-- Antes de rodar --apply em produção:
SELECT COUNT(*) FROM contabilidade_lancamentocontabil WHERE empresa_id IS NULL;
-- Se > 0, abortar e investigar origem (provavelmente INSERT direto via shell-admin).
```

Esse procedimento precisa ser adicionado ao `docs/runbooks/DL-016-F5-deploy.md` quando Frederico criá-lo (atualmente o arquivo não existe — pendência nominal para Frederico, listada em §5). Adicionalmente, DL-016-F6 vai adicionar CHECK constraint `empresa_id IS NOT NULL` como cinto-e-suspensórios.

**Veredito:** ✅ Aprovado. A decisão é defensável, documentada, e a rede de segurança não desaparece — migra para o runbook + CHECK constraint em F6.

### A2 — ACHADO MENOR — `# type: ignore[arg-type]` na linha 251 pode ser desnecessário

**Onde:** `apps/contabilidade/management/commands/backfill_lancamento_competencia.py:251`, dentro do flush final após o loop:

```python
if ids_pendentes:
    self._flushar_batch(
        ids_pendentes=ids_pendentes,
        competencia=competencia,  # type: ignore[arg-type]
        ...
    )
```

**Por que pode ser desnecessário:** o `_flushar_batch` na linha 275 já tem `if not ids_pendentes: return` como guard, e o `_executar_passada` só entra no bloco do flush final se `ids_pendentes` não-vazio. Em dry-run, o `continue` da linha 233 pula o `ids_pendentes.append(lancamento.id)` da linha 236, então se o último item do loop cai nesse continue, `ids_pendentes` está vazio e o flush final não roda — mas `competencia` no escopo do loop vira `Competencia | None` (foi a última atribuição em `cache_chaves[chave]` na linha 234 dentro do `else:` do dry-run, que só roda se `competencia is not None`). Em apply, o branch `continue` da 233 não existe (só o dry-run pula), então `competencia` é garantido não-None.

**Na prática, então:** quando `ids_pendentes` está não-vazio no flush final, `competencia` foi garantido atribuído em uma iteração anterior do loop (não a última, porque se fosse a última o `ids_pendentes.append` da 236 teria rodado). O `# type: ignore` é um cinto-e-suspensórios contra um cenário que o fluxo real não produz.

**Por que não foi consertado nesse fixup:** o escopo do fixup é a remoção do branch de órfão (causa dos 7 testes quebrados). Mexer no `# type: ignore` expande escopo (DE-007 veda). Ruff não reclama (lint status: ok), então não bloqueia o merge. Registrar como follow-up menor.

**Severidade:** menor (cosmético / type-checker noise). **Ação recomendada:** abrir issue separada (ou DE-046 quando Frederico voltar a DL-016) para remover o `# type: ignore` e refatorar `competencia` para variável local do `if` que atribui, com `mypy --strict` rodando pra confirmar.

### A3 — ACHADO MENOR — `_executar_passada` retorna `Counter` em vez de `dict` tipado

**Onde:** assinatura `def _executar_passada(...) -> Counter:` (linha 173). O `Counter` tem `__getitem__`, mas a iteração `for chave, valor in contadores_passada.items()` (linha 132) propaga para o `totais` da função `handle`, que é outro `Counter` — e isso é fragilmente correto (chaves dinâmicas, sem `TypedDict`).

**Por que é menor:** ruff não reclama, mypy não está configurado no projeto (ver `pyproject.toml`), e a API interna está consistente. Não bloqueia.

**Ação recomendada:** nenhuma agora; abrir issue se mypy for adicionado no futuro.
