Aqui o mecanismo é outro e vale nomear: `_spas_de_at_rule_com_bloco_aninhado` casa `@[\w-]+[^{}]*\{`, e `[^{}]*` atravessa o `;` e o seletor seguinte até a chave de `.cabecalho__topo` — o bloco não tem chave aninhada, então **não é reportado**, e `i` salta para depois dele. Em seguida `_extrair_regras_flat` vê um "seletor" que começa com `@` e faz `continue`. **A regra é descartada duas vezes, em silêncio.** No navegador, o `@import` no fim do arquivo é inválido e ignorado — a regra seguinte vale. Mesmo efeito com `@layer base;` e `@charset "utf-8";` (medidos por sonda direta na função: `removido=True`, isto é, a guarda afirma que a marca está escondida).

Sondagem direta das funções, para fechar o quadro:

```
controle (nada)                                -> removido=True   (guarda aprova, corretamente)
nesting reexibindo a marca                     -> removido=True   FALSO CONFORME
nesting escondendo o timbre                    -> removido=True   FALSO CONFORME
nesting com &                                  -> removido=True   FALSO CONFORME
@import antes da regra                         -> removido=True   FALSO CONFORME
@layer base; antes da regra                    -> removido=True   FALSO CONFORME
@charset antes da regra                        -> removido=True   FALSO CONFORME
segundo @media print                           -> REPROVA pedindo extensão   (correto)
@media screen (exceção nomeada)                -> removido=True   (correto)
```

**Impacto:** CSS Nesting nativo é hoje a forma **recomendada** de escrever CSS moderno e é o que qualquer pessoa que encoste neste arquivo vai usar. Não é uma construção exótica: é a evolução esperada de `static/css/base.css`. O resultado é o **vício nacional que o BL-282 existe para eliminar**, restaurado sem que nada acuse — ou, na segunda construção, o documento contábil saindo **sem emitente**.

**Classe do defeito:** **a guarda inverteu o lado seguro do JULGAMENTO e manteve a LISTA no DETECTOR.** É a oitava ocorrência da classe "lista em vez de propriedade" na etapa, deslocada mais uma casa: do prelúdio para o caractere de abertura. O BL-343 corrigiu *como decidir sobre o que vê*; não corrigiu *o que vê*.

**Correção recomendada — e ela resolve o G3 junto.** Trocar o eixo da pergunta. Em vez de classificar a at-rule pelo **prelúdio**, classificá-la pelo **conteúdo**:

1. Detectar **todo bloco com bloco aninhado**, comece ele com `@` ou com um seletor (CSS Nesting), por contagem de chaves — a mesma técnica já usada, sem o `if texto[i] == "@"`.
2. Extrair as regras de dentro. **Se nenhuma delas puder casar com um nó da cadeia de interesse** (a cadeia da marca e `.timbre-impressao`), o bloco é **comprovadamente irrelevante** e pode ser removido — qualquer que seja a condição.
3. Se **alguma** puder casar, reprovar pedindo extensão — qualquer que seja a condição, inclusive `@media screen`.
4. Reprovar também at-rule de **declaração** (`@import`, `@charset`, `@layer …;`, `@namespace`) em vez de deixá-la ser absorvida pelo prelúdio da regra seguinte.

Isso é propriedade, não lista: fecha as três construções acima **e** elimina os 19 falsos alarmes do G3, porque `@media (max-width: 48rem) { .tabela-dados { display: block } }` não toca nó nenhum da cadeia.

**Como verificar a correção:** as três construções acima devem **matar a suíte** (reprovando pedindo extensão); `@media screen { .cabecalho__topo { display: flex } }` e `@media (max-width: 48rem) { .tabela-dados { display: block } }` devem **passar**; e `.cabecalho { .cabecalho__topo { display: flex } }` medido em Chromium com `emulate_media(print)` deve continuar devolvendo `flex` — o controle de que a sabotagem é real, não hipotética.

## 6. Sobre a DE-054 — a minha opinião, como pedido

É uma boa lista — é, essencialmente, a lista do que é irreversível ou do que sai do prédio.
